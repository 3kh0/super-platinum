# Existing Canvas comment thread replies

This candidate adds replies to an existing canonical document_comment_root. It does not create a new annotation/root, edit/delete comments, or add realtime delivery. It is a successor to the separately reviewed Resolve c6534ae2 candidate, not a change to the installed reader wave.

## Source contract

The retained client chain and exact bundle hashes/offsets are pinned in tmp/canvas-comment-authoring-research-v1 (manifest d63d3e89): Canvas qhQX -> shared cCy3 Thread -> 3n5y footer -> gaG4 InputContainer -> k+EA/HNG9/gzYT -> Vy1fT chat.postMessage. Existing-root replies carry the virtual C-prefixed file channel, actual Slack root timestamp, UUID client_msg_id, text and reply_broadcast=false. No Quip thread ID is invented as a Slack timestamp. The existing public request builder is reused.

Reply admission requires current file access comment/write/owner, current document root and thread identity, no resolved root, no file lock/deletion, and no root is_locked. Additional retained i8z0/iub5 lock-selector anchors are in references/reply-guards.json. This is current-file reader mode; Canvas historical-version authoring is not introduced. The local text input has a 12,000 UTF-16-unit admission budget, explicitly a local bound rather than a Slack server maximum. Rich authoring/attachments and Enter-to-send are not implemented by this slice.

## Ownership and delivery

The existing account Canvas journal moves compatibly from schema3 to schema4. Prior structural/Resolve tables remain unchanged. Reply drafts are keyed by stable account/team/self/file/root; each native input owns a capture UUID before background save. Exact predecessors update; stale saves preserve another visible version. Capture UUID fences survive explicit review, preventing delayed cross-process resurrection. At most16 conflicting versions of one root are materialized; errors/capacity leave current local text visible and retained. Root custody holds at most32 currently non-evictable entries; only entries exactly represented in durable storage may be reclaimed. No content/history rows are automatically evicted. Immutable indexed capture/attempt history has no artificial lifetime row cap; reads are paged20 rows and each serialized body is bounded192KiB.

A deliberate Send revalidates original owner/session/Canvas visit/query and local serial after each canonical read. A transaction records the exact immutable draft plus attempt UUID before any handoff, sharing the existing file-wide structural/Resolve lock and32-in-flight account budget. Restored attempts block sending and confer no send authority. The existing Canvas single-attempt executor performs the actual chat.postMessage: pre-handoff NotSent retains the draft; everything after handoff without the exact ACK stays unknown, including generic Offline, API errors and lost responses. No queue or automatic replay is added. Shared Retry-After guards cover reads/writes and explicit review.

Settlement uses original stable account storage even after credentials or visible Canvas change. An ACK removes only its exact original draft. Newer local edits remain. Current native clearing reuses the typed existing composer receipt; a successful Changed receipt remains in original-owner custody even after navigation, while newer Rust serial/composition state wins. An in-flight native lease prevents eviction. Original settled text retained after an unavailable/retired field is marked non-sendable until deliberately edited. Storage-result retry repeats only persistence, never dispatch.

Unknown delivery has an explicit checkbox and Archive unconfirmed attempt. It freshly reads the same root and compares the complete local inventory in one transaction; no absence inference is made. Original attempt/content/root observation remain in history, and later ACK evidence attaches to the original identity without clearing another reply. When the original root cannot be read, this conservative review path retains its lock. Earlier local history is paged and never automatically resent.

## UI and native evidence boundary

The Canvas reader's typed MessageVm renderer, compact control family, scrolling region and existing owned focus helper are reused. Native input and composition events are synthetic; no trusted OS keyboard/IME evidence is claimed. Autosave persists observed input events. Abrupt process termination before an input event or before a successful save remains outside the durability claim, and storage failure is disclosed instead of navigating/sending another owner.

The new named offline fixtures are canvas-comment-reply and canvas-comment-reply-narrow, gated by SUPER_PLATINUM_CANVAS_COMMENT_REPLY_CHECK. The private replies.sqlite path must exactly equal the owned capture-ACK directory plus that basename; synthetic builder credentials never enter ShellState and no Transport/session is installed. The normal fixture without the check remains a readable thread, with no production-storage fallback.

The prepared portable runner uses NativeFixture plus existing audited capture/pointer/process helpers. For each size it runs an exercise process, waits for its audited exit, copies its exact closed private SQLite bytes into a fresh private restart directory, then starts a new process. Exercise: autosave; close/reopen; pre-handoff failure; held response with newer typing; stale canonical-root refusal; lost response. Restart: exact inventory and send lock; explicit review without replay; fresh deliberate send. Four processes and24 PNGs are planned (7+3 stages and two final captures per size). Request receipts retain actual builder method/URL/form fields with synthetic token omitted. The geometry oracle samples controls sequentially as it scrolls, not as an atomic all-controls-visible proof; every PNG still needs human image inspection by the agent.
