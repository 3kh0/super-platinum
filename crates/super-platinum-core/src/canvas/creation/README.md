## Changes

* Schema3 adds compact typed permanent terminal-attempt, archive-decision and late-result-disposition fences; existing conflict dispositions retain their exact stored bytes and UUIDs. No lifetime tombstone count limit, TTL, eviction or sequence allocator.
* Explicit schema2 migration validates the entire bounded v3 association graph before adding tables/indexes, within the same transaction. Unknown schemas/unowned databases still refuse. `legacy_integrity.rs` preserves the old finite checks for migration only. No real database was opened during authoring.
* `retirement_review(owner)` coherently captures complete bounded live owner inventory, cooldown, decisions and review references. No default selections. `RetirementSelection::new` requires exact Created ID acknowledgement; terminal retirement compares the whole review. Started/Uncertain/Reserved never retire. Active Created remains locked. Already-archived late Created after abandonment can retire without another archive/new; the historical decision is retained in content-free metadata.
* `retire_terminal` moves selected results to immutable metadata and deletes only closed obsolete graphs atomically. Newer active text/writer/revision and owner cooldown remain; current editable association detachment changes decision_revision. Already-retired retries report observation rather than a new mutation. Archived graph retirement conservatively requires all its historical attempts selected and no retained review reference.
* `retired_attempt`, `retired_archive_receipt`, and owner-indexed `retired_attempt_page` expose only metadata, never a DispatchPermit or sendable draft. Page size1..64 with keyset continuation. `RetiredAttempt::same_result` compares original immutable attempt/base/result identity, not a content hash or send permission. An old `settle` remains rejected; retired lookup is separate.
* `LateResultEvidence` stores exact original attempt/content, retained terminal result and mismatching incoming typed outcome/ID. It shares a combined16-slot review budget with conflicts. The byte budget is the existing exact content budget plus16*64KiB bounded metadata allowance, preserving valid schema2 content through migration. No metadata is stuffed into Markdown. `preserve_late_result` retries the same UUID; exact explicit disposal creates a permanent typed fence. Root custody must remain charged until commit; no root/desktop implementation is claimed here.
* Normal integrity reads audit bounded live metadata and point-lookup corresponding replay keys; they no longer scan all dispositions. Historical scopes remain durable so late captured bases survive deletion. Only active drafts have the32-owner bound; active partial-index and referenced-owner primary-key lookups avoid loading lifetime owner history. Every public read retains the v3 coherent transaction spanning audit and result.
* All operation namespaces are typed by table/API. Caller-provided conflict/archive/evidence UUIDs cannot reuse their retired identity. Generated attempts likewise probe their typed retired key before insertion. No API recreates a caller-supplied old draft ID.

SQLite syntax was checked against the official [generated-column documentation](https://www.sqlite.org/gencol.html) and [partial-index documentation](https://www.sqlite.org/partialindex.html). The actual locked bundled SQLite compiler/runtime remains authoritative. No dependency/version change.

## Limits and integration requirements

The DB grows with permanent small replay/result metadata. Disk-full/fault errors must preserve caller input and original transaction; no metadata is evicted. Count limits remain on genuinely unresolved/live content. The SQLite file is not tamper-evident: deleted/corrupted historical fences cannot be reconstructed from nothing. Unaddressed malformed historical rows do not block unrelated valid live admission; addressed rows and every live association fail closed. No auto-repair.

No Canvas durability desktop controller, root capture custody, Close/navigation fencing, history review UI or native two-process restart proof is implemented by this core module. Abrupt process death before native capture persistence and provisional IME remain outside claims. API-error allowlist remains empty/conservative and generic post-handoff Offline stays uncertain. Root source review and actual-core tests must pass before any integration. Preserve this candidate unchanged once pinned; corrections belong in a separately named successor.
